## Event ID Research

| Event ID | Description | Why It Matters |
|----------|-------------|----------------|
| 4624 | Successful Logon | Confirms a user successfully authenticated to the system. |
| 4625 | Failed Logon | Indicates an unsuccessful login attempt and may suggest password guessing or brute-force activity. |
| 4634 | Logoff | Shows when a user session ended. |
| 4672 | Special Privileges Assigned | Indicates a privileged account has logged in. |
| 1102 | Security Log Cleared | May indicate an attempt to remove evidence of malicious activity. |

## Practical Investigation

### Findings

- Multiple Event ID **4624** entries were observed.
- No Event ID **4625** (failed logons) entries were found during this investigation.

### Observation

My Windows system showed normal authentication activity with successful user logins and no failed login attempts during the review period.

---

##  SOC Scenario

### Alert

- 15 Failed Logins
- Username: Administrator
- Time: 2:14 AM
- Source: Unknown IP

### Investigation

This activity appears suspicious because:

- The **Administrator** account is a high-value target.
- The activity occurred outside normal business hours.
- Fifteen failed logins in a short period may indicate a brute-force attack.
- The source IP is unknown.

### Initial Investigation Steps

- Check if a successful login (Event ID 4624) followed the failed attempts.
- Review the reputation and geolocation of the source IP.
- Determine whether the account has logged in from this source previously.
- Check whether account lockout policies were triggered.
- Determine whether the target system is exposed to the internet.

### Recommendation

Escalate the alert for further investigation. If a successful login follows the failed attempts, treat the incident as high priority.

##  SIEM Summary

A Security Information and Event Management (SIEM) platform collects and centralizes logs from multiple systems, including endpoints, servers, firewalls, and applications.

By correlating events from different sources, a SIEM helps analysts detect suspicious activity, automate alerting, and accelerate incident response.

Examples include:

- Microsoft Sentinel
- Splunk
- IBM QRadar
- Google Chronicle

##  Knowledge Check

### Why do SOC analysts rely on logs instead of user reports?

Logs provide objective evidence of system activity with accurate timestamps, whereas users may forget details or be unaware of suspicious activity.

---

### Application Log vs Security Log

Application logs record events generated by software, such as crashes and application errors.

Security logs record authentication events, permission changes, account activity, and other security-related events used during investigations.

---

### Why is Event ID 4625 important?

It records failed authentication attempts and may indicate password guessing, brute-force attacks, or unauthorized access attempts.

---

### Why would deleting the Security log concern a SOC Analyst?

Deleting security logs removes valuable forensic evidence. Attackers often clear logs to hide their activity, making Event ID 1102 an important indicator during investigations.

---

### Why are timestamps important?

Timestamps allow analysts to reconstruct a timeline of events, correlate activity across multiple log sources, and determine the sequence of an incident.

---

##  Key Takeaways

- Windows Event Logs are one of the most important sources of evidence during incident investigations.
- Event IDs provide standardized information about system activity.
- Failed login attempts should always be investigated for potential malicious activity.
- SIEM platforms help analysts monitor, correlate, and investigate events across an organization.
